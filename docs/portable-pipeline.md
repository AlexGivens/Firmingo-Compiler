# Portable Nano preparation and independent ELF packaging

The later [declared ELF packaging contract](declared-elf-packaging.md) backs both
Swift conversion APIs and permits bounded legacy recipe declarations. The original
pinned-request `packageELF` API and its goldens below remain unchanged.

These production modules run without Swift, Node, a native compiler or device
access. They use the pinned experimental Nano contract and Web Crypto SHA-256.
They prepare source and package **independently supplied ELF**, but do not execute
WASM, prove source-to-code correspondence or qualify hardware behavior.

## Preparation and source locations

`prepareSketch(request, {signal})` snapshots the validated request, normalizes CRLF/
CR to LF, removes one initial BOM, adds `Arduino.h` and `#line 1`, and ensures a
final newline. It returns frozen request/source identities, generated translation
unit, request identity, line count and original BOM-byte count. Original source
bytes and revision remain unchanged; no function prototypes are invented.

Only literal `<Arduino.h>` or `"Arduino.h"` includes are accepted. Other directives,
macros, source-location overrides, and escaped physical newlines reject explicitly.
Byte-position-preserving masks handle comments, ordinary/character/raw literals and
numeric digit separators. Rejection emits at most 64 source diagnostics. C++ syntax,
types, unsupported facade calls, statelessness and cooperative setup/loop return are
separate compiler/linker/runtime checks; preparation does not establish them.

`originalSourceLocation(prepared, generatedLine, byteColumn)` maps physical generated
lines three onward to original-source lines; the two generated prefix lines and
invalid positions return null. Compiler diagnostics already remapped through `#line`
must not have two lines subtracted again. The first original line includes a removed
UTF-8 BOM's three bytes in its column. This intentionally corrects the SDK's earlier
preprocessor diagnostic omission for BOM-prefixed first lines; generated bytes/hashes
remain identical to the independent SDK normalization vectors. Apply the same BOM
offset once when adapting compiler locations to original byte columns.

Portable stages check a supplied AbortSignal before/after asynchronous hashing and
during bounded scans. They do not terminate synchronous WASM or enforce the full
request deadline; those belong to the runtime's worker/lifecycle. Cancellation
must not be described as hardware/upload cancellation.

## Explicit recipe and fixed jobs

The imported Nano manifest and four assets under `recipes/nano_rp2040_connect/`
are unchanged from the selected SDK commit. The original recipe hash is preserved.
`verifyNanoRecipe(manifestBytes, assets, {signal})` requires all four known paths,
checks the independently pinned manifest digest and each size/hash, snapshots inputs
before async work, and returns copied asset bytes. No arbitrary path/resource load
or service execution occurs.

`createNanoJobs(request, {signal})` prepares source and invokes the unchanged job
generator for source compile, entry compile and link. Returned response-file bytes
have fixed flags/paths and explicit API-address binding. This helper does not verify
assets or execute jobs; real runtime work must consume verified assets/service and
check actual diagnostics/status. No external libraries or conventional sysroot is
part of the stateless recipe. See its local README for provenance/attribution.

## ELF and capsule validation

`parseELF(bytes, {signal})` copies a bounded ordinary Uint8Array (including offset
views/Node Buffer views) and accepts the existing strict subset:

- 52-byte–2-MiB ELF32 little-endian ARM ET_EXEC, System V ABI zero, EABI five base/
  soft float; ordinary bounded program/section tables, no extended counts.
- One nonempty aligned readonly `.text` at `0x10200100`, 4–3840 bytes, flags `0x06`
  or LLD's reviewed merged-string `0x36`, without writable allocated sections.
- No nonempty relocation/dynamic/runtime-initializer sections, undefined/common
  symbols, incompatible addresses, overlapping metadata/code/LOAD ranges, or
  inconsistent executable file-to-memory mapping.
- Unique global Thumb setup/loop wrappers within `.text`, matching ELF setup entry,
  bounded symbol counts and canonical bounded UTF-8 string tables. A name's BOM
  is preserved rather than stripped into an alias for a required symbol.

Its returned code is copied on access. Input shared memory is rejected; bytes cannot
change during parsing/hashing. ARM headers and structural limits do not attest
Cortex-M0+ instruction selection, calling convention behavior or trusted source.

`validateCapsule(bytes, firmwareBuild, {signal})` independently checks FMS1 identity,
ABI/header/board/API/code-address fields, zero padding, exact length, Thumb entries
and code digest within the selected 4096-byte maximum. It does not parse a report,
authenticate metadata, associate a device or authorize a write. A capsule can be
structurally valid without having been compiled here or useful on hardware.

## Independent packaging and report

`packageELF(elfBytes, request, provenance, {signal})` snapshots all caller data before
async work, checks the ELF, regenerates prepared source identity, builds the FMS1
header/padding/code, and independently revalidates the capsule. It returns format,
safe `.fms` filename, copied bytes, capsule digest, static firmware requirements,
canonical report JSON and a frozen packaging receipt.

Declared provenance has exactly `compiler` (nonempty scalar text, at most 256 UTF-8
bytes, no NUL), `recipeIdentifier`, `recipeSHA256` (both match selection), and a
lowercase 64-hex `toolchainSHA256`. Syntax/matching declarations do not verify
toolchain assets or establish that the supplied ELF came from prepared source.

The report retains the SDK's capsule/source/address/digest vocabulary, with status:
`structurally validated packaging; compiler/source association is host supplied; no hardware proof`.
It includes four source/input hash paths, compiler/recipe identity, linked ELF,
capsule/code sizes and hashes, resident ELF identity and setup/loop/API addresses.
Exact golden report JSON is generated independently with Python.

## Packaging receipt and compatibility

`schemas/packaging-receipt.schema.json` identifies a distinct receipt:

```json
{
  "receiptSchema": "firmingo-compiler-packaging-v1",
  "operation": "independent_elf_packaging",
  "provenanceStatus": "declared"
}
```

This excerpt omits required fields. The complete receipt includes request/build/
revision/name identity, original/generated source digests, exact descriptor content
ID, board/profile and declared provenance. `buildInputSHA256` hashes compact sorted
JSON of those input fields only, excluding itself and `linkedELFSHA256`,
`capsuleSHA256`, `capsuleBytes`. Output hashes identify actual checked bytes.
The canonicalization matches the existing portable input rules; independent Python
goldens guard exact identity and field ordering.

This schema does not masquerade as SDK legacy/offline schema-one receipts or as a
distinct verified compilation receipt in [runtime.md](runtime.md). A wrapper adapter/versioned migration remains
necessary; source correlation, physical-device binding, fresh capabilities,
installation evidence and upload authorization stay SDK responsibilities. A changed
input revision/deadline can change the receipt while ELF/capsule bytes stay identical.

Current PipelineError codes are `invalid_source`, `unsupported_source`, `invalid_elf`,
`invalid_capsule`, `invalid_provenance`, `invalid_recipe`, and `cancelled`, with stage,
message and a bounded frozen diagnostics array. Root request/JSON/crypto errors
remain ContractError. Invalid inputs produce no artifact or device side effect.
